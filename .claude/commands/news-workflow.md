# 뉴스 수집기 기능 개발 워크플로우

아래 단계를 **순서대로** 실행한다. 모든 안내와 응답은 한국어로 한다.
브랜치 이름 인자: `$ARGUMENTS`

## 1단계: 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
2. 현재 브랜치가 `main`이 아니면:
   - 현재 브랜치 이름을 알리며 경고한다.
   - "main 브랜치로 이동할까요?"라고 사용자에게 묻고 **답을 기다린다**. 승인하면 `git checkout main`을 실행하고, 거절하면 워크플로우를 중단한다.
   - 커밋되지 않은 변경 사항이 있어 이동이 불가능하면 그 사실을 알리고 처리 방법을 묻는다.
3. `main`이면 다음 단계로 진행한다. (작업 트리에 커밋되지 않은 변경이 있으면 함께 알린다.)

## 2단계: 새 브랜치 생성

1. `$ARGUMENTS`가 비어 있지 않으면 그 값을 브랜치 이름으로 사용한다.
2. 비어 있으면:
   - "어떤 기능을 개발할 건가요?"라고 묻는다.
   - 답변을 바탕으로 **영어 소문자-하이픈 형식**(예: `add-category-filter`)의 브랜치 이름을 제안하고 확인을 받는다.
3. 이름이 이미 존재하는 브랜치와 충돌하면 알리고 다른 이름을 받는다.
4. `git checkout -b <브랜치-이름>`으로 브랜치를 만들고 이동한다.

## 3단계: 개발 시작 안내

1. 브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내한다.
2. `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 알려준다. 포함할 내용:
   - 기술 스택 (Next.js 16 App Router, Clerk, Neon + Drizzle, Claude API, Notion MCP 등)
   - 모든 페이지·API는 로그인 사용자만 접근, 모든 DB 쿼리는 Clerk `userId`로 범위 제한
   - API 키는 서버 환경변수로만 사용
   - UI 작업 전 `ui.md` 확인, Next.js 코드 작성 전 `node_modules/next/dist/docs/` 확인
   - 한국어 UI, `npm run lint` 등 주요 명령어
   - 비목표(자동 수집 스케줄링 등)와 미정 사항은 임의로 정하지 말고 사용자에게 확인
3. 이후 사용자의 개발 요청을 처리하며, 사용자가 **'완료'** 또는 **'done'** 을 입력할 때까지 4단계로 넘어가지 않는다.

## 4단계: 완료 처리 (사용자가 '완료' 또는 'done' 입력 시)

1. `git status`와 `git diff --stat`으로 **변경된 파일 목록**을 보여준다. (새 파일 포함)
2. 변경 내용을 바탕으로 커밋 메시지를 **자동으로 제안**한다. (기존 커밋 로그 스타일처럼 한국어로 간결하게. `git log --oneline -5` 참고)
3. 사용자에게 "이 메시지로 커밋할까요?"라고 묻고 **확인을 기다린다.** 수정 요청이 있으면 반영한다.
4. 확인되면:
   - 비밀 정보 파일(`.env*` 등)이 포함되지 않았는지 확인한 뒤 변경 파일을 스테이징하고 커밋한다.
   - `git checkout main`으로 이동한 뒤 `git merge <브랜치-이름>`으로 병합한다.
   - 병합 충돌이 나면 충돌 파일을 알리고 해결 방법을 사용자와 상의한다. 임의로 해결하지 않는다.
5. 푸시와 브랜치 삭제는 사용자가 요청하지 않는 한 하지 않는다.

## 5단계: 작업 요약

병합이 끝나면 다음을 요약해서 보여준다.
- 브랜치 이름과 병합 결과
- 커밋 메시지
- 변경된 파일 목록과 각 파일의 주요 변경 내용
- 구현한 기능 요약과 남은 할 일(있다면)
